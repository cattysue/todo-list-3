# todo-list-3 - Epic Breakdown

## Overview

This document provides the complete epic and story breakdown for todo-list-3, decomposing the requirements from the PRD and Architecture requirements into implementable stories.

## Requirements Inventory

### Functional Requirements

FR-1: 사용자는 로그인 후 대시보드 페이지(`/dashboard`)를 기본 진입점으로 볼 수 있다. 마감일이 있는 미완료 할일을 시간 섹션으로 자동 분류하여 표시한다. (마감일 없는 할일 및 완료된 할일 제외)

FR-2: 마감일이 오늘 이전(< today)이고 미완료인 할일을 "기한 초과" 섹션에 빨간색 시각적 강조와 함께 대시보드 최상단에 표시한다. 기한 초과 할일이 없으면 섹션을 숨긴다. 마감일 오름차순(가장 오래된 것 먼저) 정렬. 각 항목에 카테고리 이름 표시.

FR-3: 마감일이 오늘(= today)인 미완료 할일을 "오늘 마감" 섹션에 표시한다. 우선순위 내림차순 정렬. 없으면 "오늘 마감 없음" 빈 상태 메시지 표시. 우선순위 동일 시 생성 시각 기준 정렬.

FR-4: 마감일이 내일인 할일과 이번 주(오늘 이후 ~ 이번 주 일요일) 마감 할일을 별도 섹션으로 표시한다. 내일 섹션이 먼저 표시되며, 이번 주 섹션에는 내일 마감 할일이 중복 포함되지 않는다.

FR-5: 사용자는 대시보드의 각 할일 항목에서 직접 완료 체크를 할 수 있다. 완료 체크 즉시 해당 항목이 대시보드 섹션에서 사라진다. 완료 처리는 기존 카테고리 뷰에도 동기 반영된다.

FR-6: 시스템은 마감 하루 전 지정 시각과 마감 당일 아침에 사용자 이메일로 마감 요약을 발송한다. 요약 형식: "내일 마감 N개: [제목 목록]". 이미 완료된 할일 제외. 앱 대시보드로의 직접 링크 포함. 마감 전날 할일이 0개이면 발송하지 않는다.

FR-7: 사용자는 알림 시점(마감 N일/시간 전)과 발송 채널(이메일 / 브라우저 푸시)을 설정 페이지에서 변경할 수 있다. 설정 변경 즉시 다음 알림 스케줄에 반영. 알림 완전 비활성화 옵션 제공.

FR-8: 브라우저 푸시 알림 (Phase 2 후반 — NON-GOAL for MVP Phase 2-initial)

FR-9: 사용자는 검색창에 키워드를 입력하여 전체 할일 제목에서 실시간 검색 결과를 볼 수 있다. 입력 후 300ms 이내 결과 갱신(debounce 적용). 검색어 없을 때 전체 목록 표시.

FR-10: 사용자는 우선순위 / 마감일 범위 / 완료 여부 / 카테고리 필터를 개별 또는 조합하여 적용할 수 있다. 키워드 검색과 AND 조건 적용. 적용된 필터는 시각적으로 표시되며 개별 해제 가능.

FR-11: 할일 생성·수정 시 반복 주기(매일 / 매주 특정 요일 / 매월 특정 날짜)를 설정할 수 있다. 완료 시 지정 주기의 다음 마감일로 새 인스턴스 자동 생성. 기존 할일 동작에 영향 없음.

FR-12: 사용자는 반복 할일에 "이번만 건너뛰기 / 일시 중지 / 반복 종료" 옵션을 적용할 수 있다.

FR-13: 사용자는 여러 할일을 묶어 이름을 붙인 템플릿을 저장하고, 언제든 불러와 한 번에 여러 할일을 생성할 수 있다.

FR-14: 사용자는 캘린더 탭에서 마감일 기준 월간/주간 뷰로 할일을 볼 수 있다. 날짜 클릭 시 해당 날의 할일 목록 표시.

FR-15: 캘린더 뷰에서 할일을 다른 날짜로 드래그하면 마감일이 자동으로 변경된다. 즉시 대시보드와 카테고리 뷰에 반영.

FR-16: 사용자는 통계 페이지에서 주간/월간 완료 개수와 완료율을 차트로 볼 수 있다.

FR-17: 사용자는 카테고리별 완료율을 비교하여 어느 영역에서 실행력이 떨어지는지 확인할 수 있다.

## Epic 1: 시간 중심 대시보드

앱을 열었을 때 기한 초과·오늘·내일·이번 주 할일을 한눈에 파악하고, 그 자리에서 바로 완료 처리할 수 있다.

### Story 1.1: 마감일 기준 대시보드 API 구축

사용자(Catty)로서,
FastAPI가 마감일을 기준으로 할일을 섹션별로 분류하여 반환하는 `/todos/dashboard` 엔드포인트를 원한다,
클라이언트 사이드에서 날짜 계산 없이 대시보드 UI를 구성할 수 있도록.

**Acceptance Criteria:**

**Given** Supabase `todos` 테이블에 `due_date` 컬럼이 존재할 때
**When** 데이터베이스 마이그레이션(`add_due_date_index.sql`)을 실행하면
**Then** `idx_todos_due_date` 인덱스가 생성된다
**And** 인덱스가 없을 때보다 마감일 필터 쿼리 응답이 빨라진다

**Given** 인증된 사용자가 `GET /todos/dashboard`를 호출할 때
**When** 서버의 오늘 날짜(UTC)를 기준으로 할일을 분류하면
**Then** `{"overdue": [...], "today": [...], "tomorrow": [...], "this_week": [...]}` 형식의 응답이 반환된다
**And** 마감일이 없는 할일과 완료된 할일은 모든 섹션에서 제외된다

**Given** API 응답의 `overdue` 목록일 때
**When** 정렬을 적용하면
**Then** 마감일 오름차순(가장 오래된 것 먼저)으로 정렬된다
**And** 각 할일 객체에 카테고리 이름(`category_name`)이 포함된다

**Given** API 응답의 `today` 목록일 때
**When** 정렬을 적용하면
**Then** 우선순위 내림차순(높음→중간→낮음)으로 정렬된다
**And** 우선순위가 동일하면 `created_at` 오름차순으로 정렬된다

**Given** `this_week` 섹션에 포함될 할일 목록일 때
**When** 섹션을 채우면
**Then** `tomorrow` 섹션에 포함된 할일은 `this_week`에 중복 포함되지 않는다

**Given** 인증되지 않은 요청이 들어올 때
**When** `GET /todos/dashboard`를 호출하면
**Then** `401 Unauthorized`가 반환된다

### Story 1.2: 대시보드 페이지 레이아웃 및 데이터 패칭 구축

사용자(Catty)로서,
로그인 후 자동으로 이동하는 `/dashboard` 페이지에서 마감일 기준 할일 데이터를 불러오는 것을 원한다,
카테고리를 탐색하지 않고도 할일이 시간 섹션으로 구조화되어 보이는 전용 공간을 갖도록.

**Acceptance Criteria:**

**Given** `lib/queryKeys.ts`가 생성되었을 때
**When** TanStack Query를 사용하는 어떤 파일에서든
**Then** `queryKeys.todos.dashboard()`, `queryKeys.todos.all` 등 중앙화된 키로만 쿼리에 접근한다
**And** 컴포넌트·훅 파일 내에서 쿼리 키 문자열 리터럴을 직접 사용하지 않는다

**Given** 사용자가 로그인한 상태일 때
**When** 앱 루트(`/`)에 접근하면
**Then** `/dashboard`로 자동 리다이렉트된다

**Given** `/dashboard` 페이지에 접근할 때
**When** 데이터를 로딩 중이면
**Then** `app/dashboard/loading.tsx`의 스켈레톤 UI가 표시된다
**And** 레이아웃이 깨지지 않는다

**Given** `/dashboard` 페이지에서 데이터 로딩이 완료되었을 때
**When** 페이지가 렌더링되면
**Then** "기한 초과", "오늘 마감", "내일 마감", "이번 주 마감" 섹션 영역이 각각 존재한다
**And** `hooks/useDashboard.ts`가 `lib/api.ts`를 통해 `GET /todos/dashboard`를 호출한다

**Given** API 호출이 실패할 때
**When** 네트워크 에러 또는 서버 에러가 발생하면
**Then** 앱이 크래시되지 않고 빈 섹션들이 표시된다
**And** 한국어 에러 메시지가 토스트 또는 에러 영역에 표시된다

### Story 1.3: 시간 섹션 컴포넌트 구현 (기한 초과·오늘·내일·이번 주)

사용자(Catty)로서,
대시보드의 각 섹션이 올바른 할일을 적절한 시각적 스타일과 정렬로 표시하는 것을 원한다,
기한 초과·오늘·내일·이번 주에 해당하는 할일을 구분하여 즉시 파악할 수 있도록.

**Acceptance Criteria:**

**Given** 기한 초과 할일이 1개 이상 존재할 때
**When** 대시보드가 렌더링되면
**Then** "기한 초과" 섹션이 다른 모든 섹션보다 최상단에 표시된다
**And** 빨간색 시각적 강조(헤더 색상 또는 항목 테두리)가 적용된다
**And** 각 항목에 카테고리 이름이 표시된다

**Given** 기한 초과 할일이 0개일 때
**When** 대시보드가 렌더링되면
**Then** "기한 초과" 섹션 자체가 DOM에 렌더링되지 않는다

**Given** 오늘 마감 할일이 1개 이상 존재할 때
**When** "오늘 마감" 섹션이 렌더링되면
**Then** 우선순위 내림차순(높음→중간→낮음)으로 정렬된 목록이 표시된다
**And** 우선순위가 동일한 항목은 `created_at` 오름차순으로 정렬된다

**Given** 오늘 마감 할일이 0개일 때
**When** "오늘 마감" 섹션이 렌더링되면
**Then** 목록 대신 "오늘 마감 없음" 빈 상태 메시지가 표시된다

**Given** 내일 마감 할일과 이번 주 마감 할일이 각각 존재할 때
**When** 대시보드가 렌더링되면
**Then** "내일 마감" 섹션과 "이번 주 마감" 섹션이 각각 독립적으로 렌더링된다
**And** "이번 주 마감" 섹션에 내일 마감 할일이 중복 표시되지 않는다

**Given** 내일 마감 섹션과 이번 주 마감 섹션이 함께 표시될 때
**When** 렌더링 순서를 확인하면
**Then** "내일 마감" 섹션이 "이번 주 마감" 섹션보다 먼저 표시된다

### Story 1.4: 대시보드에서 할일 완료 처리

사용자(Catty)로서,
대시보드의 각 할일 항목에서 직접 완료 체크를 하는 것을 원한다,
카테고리 뷰로 이동하지 않고도 그 자리에서 바로 할일을 처리할 수 있도록.

**Acceptance Criteria:**

**Given** 대시보드의 어떤 섹션에서든 할일이 표시되어 있을 때
**When** 완료 체크박스를 클릭하면
**Then** 해당 항목이 즉시 해당 섹션에서 사라진다 (낙관적 업데이트)
**And** 완료 처리 API 호출이 백그라운드에서 진행된다

**Given** 완료 처리 API 호출이 성공했을 때
**When** 서버 응답이 도착하면
**Then** `queryKeys.todos.all` 캐시가 무효화되어 카테고리 뷰도 완료 상태로 갱신된다

**Given** 완료 처리 중 네트워크 오류가 발생했을 때
**When** API 호출이 실패하면
**Then** 낙관적 업데이트가 롤백되어 해당 할일이 섹션에 다시 표시된다
**And** 한국어 에러 메시지가 표시된다

**Given** 완료 처리 mutation이 진행 중일 때
**When** UI가 서버 응답을 기다리는 상태이면
**Then** 해당 체크박스가 비활성화되어 중복 클릭이 방지된다

## Epic 2: 스마트 마감 알림

앱을 열지 않아도 마감 임박 할일을 이메일로 사전에 통보받고, 알림 시점과 채널을 개인화할 수 있다.

### Story 2.1: 이메일 알림 스케줄링 인프라 구축

사용자(Catty)로서,
Railway Cron Job이 정해진 시각에 FastAPI 알림 엔드포인트를 호출하는 스케줄링 인프라를 원한다,
이메일 알림과 향후 반복 할일(Phase 3)이 모두 사용할 수 있는 공통 자동화 기반을 갖추도록.

**Acceptance Criteria:**

**Given** Railway 프로젝트에 Cron Job이 설정되었을 때
**When** 지정된 시각(기본: 매일 오전 9시)이 되면
**Then** FastAPI의 알림 트리거 엔드포인트(`POST /notifications/trigger`)가 자동으로 호출된다
**And** Cron Job 실행 로그가 Railway 대시보드에서 확인된다

**Given** FastAPI `services/email.py`가 구현되었을 때
**When** 이메일 발송 함수를 호출하면
**Then** 선택된 이메일 서비스(Resend 또는 SendGrid)를 통해 이메일이 발송된다
**And** API 키는 Railway 환경 변수에서 로드되며 코드에 하드코딩되지 않는다

**Given** 알림 트리거 엔드포인트가 호출될 때
**When** 내부 Cron Job 시크릿 키가 헤더에 없거나 잘못되면
**Then** `401 Unauthorized`가 반환되어 외부 무단 호출이 차단된다

### Story 2.2: 마감 임박 이메일 알림 발송

사용자(Catty)로서,
마감 하루 전과 당일 아침에 미완료 할일 요약을 이메일로 받는 것을 원한다,
앱을 열지 않아도 오늘과 내일 마감 할일을 미리 파악할 수 있도록.

**Acceptance Criteria:**

**Given** Railway Cron Job이 알림 트리거를 호출할 때
**When** 내일 마감인 미완료 할일이 1개 이상 존재하면
**Then** "내일 마감 N개: [제목1, 제목2, ...]" 형식의 요약 이메일이 발송된다
**And** 이메일 본문에 앱 `/dashboard`로의 직접 링크가 포함된다

**Given** Railway Cron Job이 알림 트리거를 호출할 때
**When** 내일 마감인 미완료 할일이 0개이면
**Then** 이메일이 발송되지 않는다

**Given** 이메일 발송 대상 할일 목록을 조회할 때
**When** 이미 완료 처리된 할일이 존재하면
**Then** 해당 할일은 알림 대상에서 제외된다

**Given** 당일 마감 알림이 발송될 때
**When** 오늘 마감인 미완료 할일이 존재하면
**Then** "오늘 마감 N개: [제목 목록]" 형식의 이메일이 발송된다

**Given** 이메일 서비스 API 호출이 실패할 때
**When** 발송 중 오류가 발생하면
**Then** 예외가 catch되어 FastAPI 서버가 크래시되지 않는다
**And** 에러가 서버 로그에 기록된다

### Story 2.3: 알림 개인화 설정 페이지

사용자(Catty)로서,
알림 시점과 채널을 설정 페이지에서 직접 변경하고 알림 자체를 비활성화하는 것을 원한다,
나의 생활 패턴에 맞는 알림 방식을 스스로 제어할 수 있도록.

**Acceptance Criteria:**

**Given** 사용자가 `/settings` 페이지에 접근할 때
**When** 알림 설정 섹션을 확인하면
**Then** 현재 알림 활성화 여부, 알림 시점(마감 N일 전), 발송 채널(이메일) 설정이 표시된다

**Given** 사용자가 알림 시점을 변경하고 저장할 때
**When** 설정이 저장되면
**Then** 다음 Cron Job 실행부터 변경된 시점 기준으로 알림이 발송된다
**And** 저장 성공 메시지가 한국어로 표시된다

**Given** 사용자가 알림 완전 비활성화 옵션을 선택하고 저장할 때
**When** 설정이 저장되면
**Then** 이후 Cron Job 실행 시 해당 사용자에게 이메일이 발송되지 않는다

**Given** 설정 페이지에서 저장 요청이 실패할 때
**When** API 에러가 발생하면
**Then** 이전 설정값이 유지되며 한국어 에러 메시지가 표시된다

## Epic 3: 할일 검색 및 고급 필터링

할일 수가 많아져도 키워드 검색과 우선순위·날짜·카테고리 복합 필터로 원하는 할일에 즉시 접근할 수 있다.

### Story 3.1: 키워드 실시간 검색

사용자(Catty)로서,
검색창에 키워드를 입력하면 전체 할일 제목에서 실시간으로 결과를 확인하는 것을 원한다,
수많은 할일 중 특정 할일을 빠르게 찾을 수 있도록.

**Acceptance Criteria:**

**Given** 사용자가 검색창에 키워드를 입력할 때
**When** 마지막 입력으로부터 300ms가 경과하면
**Then** 해당 키워드를 제목에 포함하는 할일 목록이 표시된다
**And** 300ms 이내 연속 입력 시에는 API 호출이 발생하지 않는다 (debounce)

**Given** 검색창에 키워드가 입력되어 있지 않을 때
**When** 검색 결과 영역이 렌더링되면
**Then** 빈 결과가 아닌 전체 할일 목록이 표시된다

**Given** 검색 키워드가 어떤 할일 제목과도 일치하지 않을 때
**When** 검색 결과가 반환되면
**Then** "검색 결과 없음" 빈 상태 메시지가 표시된다

**Given** 검색 결과가 표시될 때
**When** 각 결과 항목을 확인하면
**Then** 할일 제목, 마감일, 우선순위, 카테고리 이름이 함께 표시된다

### Story 3.2: 고급 복합 필터링

사용자(Catty)로서,
우선순위·마감일 범위·완료 여부·카테고리 필터를 개별 또는 조합하여 적용하는 것을 원한다,
키워드 검색과 함께 사용하여 정확히 원하는 할일 목록을 즉시 추릴 수 있도록.

**Acceptance Criteria:**

**Given** 필터 UI가 표시되어 있을 때
**When** 우선순위, 마감일 범위, 완료 여부, 카테고리 중 하나 이상을 선택하면
**Then** 선택된 필터 조건이 AND 조건으로 적용된 할일 목록이 표시된다

**Given** 키워드 검색과 필터가 동시에 적용되어 있을 때
**When** 결과 목록이 렌더링되면
**Then** 키워드 AND 필터 조건을 모두 만족하는 할일만 표시된다

**Given** 하나 이상의 필터가 적용되어 있을 때
**When** 필터 영역을 확인하면
**Then** 적용된 각 필터가 태그(칩) 형태로 시각적으로 표시된다
**And** 각 태그의 삭제 버튼을 클릭하면 해당 필터만 개별 해제된다

**Given** "이번 주 마감 + 높은 우선순위 + 미완료" 필터 조합을 적용할 때
**When** 결과가 반환되면
**Then** 세 조건을 모두 만족하는 할일만 표시된다

**Given** 적용된 모든 필터를 해제할 때
**When** 필터가 초기화되면
**Then** 전체 할일 목록이 다시 표시된다

## Epic 4: 반복 할일 자동화 + 템플릿

매일 반복되는 루틴을 자동화하고, 자주 쓰는 할일 묶음을 한 번에 생성하여 수동 입력 부담을 없앨 수 있다.

### Story 4.1: 반복 주기 설정

사용자(Catty)로서,
할일을 생성하거나 수정할 때 반복 주기(매일/매주/매월)를 설정하는 것을 원한다,
루틴 할일을 한 번만 등록하면 자동으로 반복되도록.

**Acceptance Criteria:**

**Given** 할일 생성 또는 수정 폼이 열려 있을 때
**When** 반복 주기 옵션을 확인하면
**Then** "반복 없음 / 매일 / 매주 (요일 선택) / 매월 (날짜 선택)" 선택지가 제공된다

**Given** 반복 주기가 설정된 할일을 저장할 때
**When** DB에 저장되면
**Then** `todos` 테이블(또는 별도 `recurrence` 테이블)에 반복 주기 정보가 저장된다
**And** 기존 반복 설정이 없는 할일의 동작에 영향이 없다

**Given** 매주 반복을 선택할 때
**When** 요일을 지정하면
**Then** 지정된 요일 정보가 반복 설정에 저장된다

**Given** 매월 반복을 선택할 때
**When** 날짜를 지정하면
**Then** 지정된 날짜 정보가 반복 설정에 저장된다

### Story 4.2: 반복 할일 자동 재생성

사용자(Catty)로서,
반복 주기가 설정된 할일을 완료하면 다음 주기의 인스턴스가 자동으로 생성되는 것을 원한다,
매일 직접 입력하지 않아도 루틴 할일이 대시보드에 자동으로 나타나도록.

**Acceptance Criteria:**

**Given** 반복 주기가 설정된 할일을 완료 처리할 때
**When** 완료 API가 호출되면
**Then** 지정된 주기의 다음 마감일로 새 할일 인스턴스가 자동 생성된다
**And** 새 인스턴스는 원본 할일과 동일한 제목·카테고리·우선순위를 가진다

**Given** 매일 반복 할일을 완료할 때
**When** 새 인스턴스가 생성되면
**Then** 마감일이 오늘로부터 +1일로 설정된다

**Given** 매주 반복 할일을 완료할 때
**When** 새 인스턴스가 생성되면
**Then** 마감일이 지정된 요일 기준 다음 주로 설정된다

**Given** 매월 반복 할일을 완료할 때
**When** 새 인스턴스가 생성되면
**Then** 마감일이 다음 달 지정 날짜로 설정된다

**Given** 반복 주기가 없는 일반 할일을 완료할 때
**When** 완료 API가 호출되면
**Then** 새 인스턴스가 생성되지 않고 기존 동작이 유지된다

### Story 4.3: 반복 유연 제어

사용자(Catty)로서,
반복 할일에 "이번만 건너뛰기 / 일시 중지 / 반복 종료" 옵션을 적용하는 것을 원한다,
예외적인 상황에서도 반복 패턴을 유연하게 조절할 수 있도록.

**Acceptance Criteria:**

**Given** 반복 주기가 설정된 할일이 표시되어 있을 때
**When** 해당 할일의 옵션 메뉴를 열면
**Then** "이번만 건너뛰기", "일시 중지", "반복 종료" 옵션이 표시된다

**Given** "이번만 건너뛰기"를 선택할 때
**When** 동작이 실행되면
**Then** 현재 인스턴스가 완료 처리 없이 건너뛰어지고 다음 주기 인스턴스가 생성된다
**And** 반복 설정 자체는 유지된다

**Given** "일시 중지"를 선택할 때
**When** 동작이 실행되면
**Then** 현재 인스턴스 이후 새 인스턴스가 생성되지 않는다
**And** 재개 옵션이 표시되어 언제든 반복을 다시 활성화할 수 있다

**Given** 일시 중지된 반복 할일에서 재개를 선택할 때
**When** 재개가 활성화되면
**Then** 다음 주기 마감일로 새 인스턴스가 생성된다

**Given** "반복 종료"를 선택할 때
**When** 동작이 실행되면
**Then** 현재 인스턴스 이후 더 이상 새 인스턴스가 생성되지 않는다
**And** 반복 설정이 제거되어 일반 할일로 전환된다

### Story 4.4: 할일 묶음 템플릿

사용자(Catty)로서,
자주 사용하는 할일 조합을 템플릿으로 저장하고 원클릭으로 여러 할일을 한 번에 생성하는 것을 원한다,
반복적으로 같은 할일들을 개별 입력하는 번거로움을 없애도록.

**Acceptance Criteria:**

**Given** 사용자가 여러 할일을 선택하거나 템플릿 생성 폼을 작성할 때
**When** 이름을 붙여 템플릿으로 저장하면
**Then** 해당 할일 묶음이 템플릿으로 저장된다
**And** 저장된 템플릿 목록에서 확인할 수 있다

**Given** 저장된 템플릿을 불러오기할 때
**When** 불러오기를 실행하면
**Then** 템플릿에 포함된 모든 할일이 즉시 생성된다
**And** 생성된 할일들이 카테고리 뷰와 대시보드에 즉시 반영된다

**Given** 템플릿을 불러올 때 마감일 처리 방식을 선택할 때
**When** "오늘 기준 자동 설정" 또는 "직접 지정" 중 하나를 선택하면
**Then** 선택한 방식대로 생성된 할일들의 마감일이 설정된다

**Given** 저장된 템플릿 목록이 표시될 때
**When** 특정 템플릿을 삭제하면
**Then** 해당 템플릿이 목록에서 제거된다
**And** 이미 생성된 할일들에는 영향이 없다

## Epic 5: 캘린더 뷰

마감일 기준으로 할일의 분포를 월간/주간 달력에서 시각적으로 파악하고, 드래그로 마감일을 즉시 조정할 수 있다.

### Story 5.1: 캘린더 뷰 페이지 구현

사용자(Catty)로서,
캘린더 탭에서 마감일 기준 월간/주간 달력으로 할일을 보는 것을 원한다,
마감이 몰린 날과 여유로운 날을 시각적으로 한눈에 파악할 수 있도록.

**Acceptance Criteria:**

**Given** 사용자가 `/calendar` 페이지에 접근할 때
**When** 페이지가 렌더링되면
**Then** 월간 뷰와 주간 뷰 전환 탭이 표시된다
**And** 마감일이 있는 할일들이 해당 날짜 셀에 표시된다

**Given** 캘린더의 특정 날짜를 클릭할 때
**When** 날짜 셀을 선택하면
**Then** 해당 날짜의 할일 목록이 상세 패널 또는 모달로 표시된다
**And** 각 할일의 제목·우선순위·완료 여부가 표시된다

**Given** 마감일이 많은 날짜가 있을 때
**When** 달력 셀에 표시할 수 있는 할일 수를 초과하면
**Then** 초과 개수(예: "+2개 더")가 표시된다

**Given** 월간/주간 뷰 전환 탭을 클릭할 때
**When** 뷰가 전환되면
**Then** 선택된 뷰에 맞는 달력 레이아웃으로 즉시 전환된다

### Story 5.2: 드래그로 마감일 변경

사용자(Catty)로서,
캘린더 뷰에서 할일을 다른 날짜로 드래그하여 마감일을 변경하는 것을 원한다,
날짜 수정 폼을 열지 않고도 일정을 직관적으로 재조정할 수 있도록.

**Acceptance Criteria:**

**Given** 캘린더 뷰에서 할일 항목이 표시되어 있을 때
**When** 할일을 다른 날짜 셀로 드래그하여 놓으면
**Then** 해당 할일의 마감일이 드롭된 날짜로 변경된다
**And** 캘린더에서 해당 할일이 새 날짜 셀로 즉시 이동된다

**Given** 드래그로 마감일 변경이 완료되었을 때
**When** 서버에 변경사항이 저장되면
**Then** 대시보드 뷰와 카테고리 뷰에도 변경된 마감일이 반영된다

**Given** 드래그 중 서버 저장이 실패할 때
**When** API 에러가 발생하면
**Then** 할일이 원래 날짜로 롤백되어 캘린더에 다시 표시된다
**And** 한국어 에러 메시지가 표시된다

**Given** 드래그 동작이 진행 중일 때
**When** 할일을 다른 날짜 위로 이동하면
**Then** 드롭 가능한 날짜 셀이 시각적으로 강조되어 정확한 날짜에 놓을 수 있다

## Epic 6: 생산성 통계

주간/월간 완료율과 카테고리별 실행력을 차트로 확인하여 자신의 생산성 패턴을 발견할 수 있다.

### Story 6.1: 주간·월간 완료율 통계 차트

사용자(Catty)로서,
통계 페이지에서 주간·월간 완료 개수와 완료율을 차트로 보는 것을 원한다,
내 생산성이 시간에 따라 어떻게 변화하는지 데이터로 파악할 수 있도록.

**Acceptance Criteria:**

**Given** 사용자가 `/stats` 페이지에 접근할 때
**When** 페이지가 렌더링되면
**Then** 주간 뷰와 월간 뷰 전환 탭이 표시된다
**And** 선택된 기간의 완료 개수와 완료율이 차트로 표시된다

**Given** 주간 뷰가 선택되어 있을 때
**When** 차트가 렌더링되면
**Then** 최근 N주간 각 주의 완료 개수와 완료율이 표시된다

**Given** 월간 뷰가 선택되어 있을 때
**When** 차트가 렌더링되면
**Then** 최근 N개월간 각 월의 완료 개수와 완료율이 표시된다

**Given** 통계 집계 API를 호출할 때
**When** 서버에서 데이터를 조회하면
**Then** 완료된 할일의 `completed_at` 기준으로 기간별 집계가 반환된다
**And** 마감일 없이 완료된 할일도 집계에 포함된다

### Story 6.2: 카테고리별 완료율 분석

사용자(Catty)로서,
카테고리별 완료율을 비교하는 차트를 보는 것을 원한다,
어느 영역의 할일을 잘 처리하고 어느 영역에서 실행력이 떨어지는지 파악할 수 있도록.

**Acceptance Criteria:**

**Given** 사용자가 `/stats` 페이지의 카테고리 분석 섹션에 접근할 때
**When** 차트가 렌더링되면
**Then** 각 카테고리별 완료율(완료 수 / 전체 수)이 비교 차트로 표시된다
**And** 완료율이 높은 카테고리와 낮은 카테고리를 한눈에 구분할 수 있다

**Given** 카테고리별 완료율 집계 API를 호출할 때
**When** 서버에서 데이터를 조회하면
**Then** 카테고리별 전체 할일 수와 완료 할일 수, 완료율이 반환된다

**Given** 할일이 없는 카테고리가 존재할 때
**When** 차트가 렌더링되면
**Then** 해당 카테고리는 차트에서 제외되거나 "데이터 없음"으로 표시된다

**Given** 통계 페이지 전체가 표시될 때
**When** 주간·월간 완료율 차트(Story 6.1)와 카테고리별 분석 차트가 함께 렌더링되면
**Then** 두 섹션이 하나의 `/stats` 페이지 내에 구분된 영역으로 표시된다
