# PRD: todo-list-3 기능 확장

## 0. 문서 목적

이 PRD는 todo-list-3의 기능 확장 전체 로드맵을 정의한다. 대상 독자는 개발자(Catty 본인)이며, 4개 Phase로 구성된 단계적 구현의 판단 기준과 요구사항을 담는다. 기능 요구사항은 FR-N으로 전역 번호가 부여되어 에픽·스토리 산출물에서 안정적으로 참조된다. MVP(Phase 1) 범위와 이후 단계를 명확히 구분하여 구현 우선순위를 보장한다.

---

## 1. 비전

todo-list-3는 현재 카테고리 기반 할일 관리 앱이다. 핵심 데이터인 마감일과 우선순위는 이미 존재하지만, 이 데이터를 활용해 사용자에게 "지금 뭘 해야 하는가"를 즉시 보여주지 못하고 있다.

이번 확장의 핵심 전환은 **카테고리 중심 → 시간 중심**이다. 사용자가 앱을 열었을 때 오늘 마감, 기한 초과, 이번 주 할일이 자동으로 집계되어 한눈에 보이도록 한다. 추가로 알림, 탐색, 반복 자동화, 시각적 캘린더, 생산성 통계를 단계적으로 추가하여 최종적으로는 **개인 생산성 워크플로우 허브**로 진화시킨다.

성공의 정의는 단순하다: Catty 본인이 이 앱을 매일 실제로 사용하게 되는 것.

---

## 2. 대상 사용자

### 2.1 주요 페르소나

**Catty — 개발자이자 유일한 사용자**
Next.js·FastAPI·Supabase 스택을 직접 구축한 개발자로, 자신이 만든 앱을 실제 일상 생산성 도구로 사용하고자 한다. 카테고리별로 할일을 관리하고 있지만, 여러 카테고리에 흩어진 오늘 마감 할일을 한 번에 보고 싶다는 명확한 불편함을 갖고 있다.

### 2.2 해결할 작업 (Jobs To Be Done)

- **기능적:** 앱을 열었을 때 오늘 당장 해야 할 일을 3초 안에 파악하고 싶다.
- **기능적:** 기한이 지난 할일을 놓치지 않고 인지하고 싶다.
- **기능적:** 앱을 열지 않아도 마감이 다가오는 것을 알고 싶다.
- **기능적:** 매일 반복되는 루틴 입력을 자동화하고 싶다.
- **감성적:** 할일이 쌓여도 앱이 나를 압도하지 않고 우선순위를 보여줘야 한다.
- **자기인식:** 어느 영역 할일을 잘 처리하고 어느 영역에서 실행력이 떨어지는지 파악하고 싶다.

### 2.3 주요 사용자 여정

- **UJ-1. Catty가 아침에 앱을 열고 오늘 할 일을 파악한다.**
  로그인된 상태. 앱 홈(대시보드)에 진입하면 "기한 초과 / 오늘 마감 / 내일 / 이번 주" 섹션이 자동으로 렌더링된다. Catty는 스크롤 없이 오늘 마감 할일 목록을 보고 우선순위를 잡는다. 완료 체크를 하면 해당 항목이 섹션에서 사라진다.

- **UJ-2. Catty가 어제 놓친 할일을 처리한다.**
  앱 진입 시 대시보드 최상단에 빨간색으로 강조된 "기한 초과" 섹션이 보인다. Catty는 목록을 확인하고 완료하거나 마감일을 재설정한다.

- **UJ-3. Catty가 앱 밖에서 마감 알림을 받고 앱에 진입한다.**
  마감 하루 전 이메일이 도착한다. "내일 마감 2개" 요약을 보고 앱에 접속하여 대시보드에서 해당 항목을 확인한다.

- **UJ-4. Catty가 매일 아침 루틴 할일을 자동으로 받는다.**
  반복 주기를 설정한 할일이 매일 자동으로 생성되어 오늘 마감 섹션에 나타난다. 완료 체크 시 다음 날 자동으로 재생성된다.

## 3. 용어 정의

| 용어 | 정의 |
|------|------|
| **할일(Todo)** | 제목, 마감일, 우선순위, 완료 여부, 카테고리를 가진 작업 단위 |
| **카테고리(Category)** | 할일을 묶는 사용자 정의 그룹. 1개의 할일은 1개의 카테고리에 속한다 |
| **마감일(Due Date)** | 할일에 설정된 완료 목표 날짜. 없을 수 있다 |
| **우선순위(Priority)** | 높음 / 중간 / 낮음 3단계 |
| **기한 초과(Overdue)** | 마감일이 오늘 이전이고 아직 미완료인 할일 |
| **오늘 마감(Today)** | 마감일이 오늘인 미완료 할일 |
| **대시보드(Dashboard)** | 시간 기준으로 할일을 자동 집계해 보여주는 앱의 메인 화면 |
| **반복 할일(Recurring Todo)** | 주기(매일/매주/매월)에 따라 완료 시 자동으로 다음 인스턴스가 생성되는 할일 |
| **템플릿(Template)** | 자주 사용하는 할일 묶음을 저장해둔 재사용 단위 |

## 4. 기능

### 4.1 시간 중심 대시보드 *(Phase 1 — MVP)*

**설명:** 앱의 메인 화면을 시간 축 기반 대시보드로 전환한다. 로그인한 사용자가 앱을 열었을 때, 마감일 기준으로 자동 집계된 할일 목록이 "기한 초과 → 오늘 마감 → 내일 마감 → 이번 주 마감" 순서로 표시된다. 사용자는 카테고리를 탐색하지 않아도 지금 당장 무엇을 해야 하는지 즉시 파악한다. UJ-1, UJ-2를 실현한다.

**기능 요구사항:**

#### FR-1: 대시보드 메인 페이지

사용자는 로그인 후 대시보드 페이지(`/dashboard`)를 기본 진입점으로 볼 수 있다. 마감일이 있는 미완료 할일을 시간 섹션으로 자동 분류하여 표시한다.

**결과 (테스트 가능):**
- 로그인 후 `/dashboard`로 리다이렉트된다.
- 마감일이 없는 할일은 대시보드에 표시되지 않는다.
- 마감일이 있는 완료된 할일은 대시보드에 표시되지 않는다.

#### FR-2: 기한 초과 섹션

마감일이 오늘 이전(< today)이고 미완료인 할일을 "기한 초과" 섹션에 빨간색 시각적 강조와 함께 대시보드 최상단에 표시한다. UJ-2를 실현한다.

**결과 (테스트 가능):**
- 기한 초과 할일이 없으면 해당 섹션이 숨겨진다.
- 기한 초과 할일은 마감일 오름차순(가장 오래된 것이 먼저)으로 정렬된다.
- 각 항목에 카테고리 이름이 표시된다.

#### FR-3: 오늘 마감 섹션

마감일이 오늘(= today)인 미완료 할일을 "오늘 마감" 섹션에 표시한다. 우선순위 내림차순으로 정렬한다.

**결과 (테스트 가능):**
- 오늘 마감 할일이 없으면 "오늘 마감 없음" 빈 상태 메시지를 표시한다.
- 우선순위가 동일한 경우 생성 시각 기준으로 정렬된다.

#### FR-4: 내일 / 이번 주 마감 섹션

마감일이 내일인 할일과 이번 주(오늘 이후 ~ 이번 주 일요일) 마감 할일을 별도 섹션으로 표시한다. 내일 항목이 먼저 표시된다.

**결과 (테스트 가능):**
- 내일 섹션과 이번 주 섹션이 각각 독립 렌더링된다.
- 이번 주 섹션에는 내일 마감 할일이 중복 포함되지 않는다.

#### FR-5: 대시보드에서 완료 처리

사용자는 대시보드의 각 할일 항목에서 직접 완료 체크를 할 수 있다.

**결과 (테스트 가능):**
- 완료 체크 즉시 해당 항목이 대시보드 섹션에서 사라진다.
- 완료 처리는 기존 카테고리 뷰에도 동기 반영된다.

**기능별 NFR:**
- 대시보드 초기 로드 응답 시간 < 1초 (Supabase 쿼리 최적화, 마감일 인덱스 필수)

### 4.2 스마트 마감 알림 *(Phase 2)*

**설명:** 사용자가 앱을 열지 않아도 마감이 다가오는 것을 알 수 있도록, 마감 전날과 당일 이메일 알림을 발송한다. 이후 브라우저 푸시 알림을 추가한다. 사용자는 알림 시점과 채널을 개인화 설정할 수 있다. UJ-3을 실현한다.

**기능 요구사항:**

#### FR-6: 이메일 마감 알림

시스템은 마감 하루 전 지정 시각과 마감 당일 아침에 사용자 이메일로 마감 요약을 발송한다. 요약 형식: "내일 마감 N개: [제목 목록]".

**결과 (테스트 가능):**
- 마감 하루 전 할일이 0개이면 이메일이 발송되지 않는다.
- 이메일에는 앱 대시보드로의 직접 링크가 포함된다.
- 이미 완료된 할일은 알림에 포함되지 않는다.

**범위 외:** 이 FR에서는 브라우저 푸시를 구현하지 않는다 (FR-8 참조).

#### FR-7: 알림 개인화 설정

사용자는 알림 시점(마감 N일/시간 전)과 발송 채널(이메일 / 브라우저 푸시)을 설정 페이지에서 변경할 수 있다.

**결과 (테스트 가능):**
- 설정 변경 즉시 다음 알림 스케줄에 반영된다.
- 알림 완전 비활성화 옵션이 있다.

#### FR-8: 브라우저 푸시 알림 `[NON-GOAL for MVP Phase 2-initial]`

이메일 알림 안정화 후 추가. Web Push API 또는 Service Worker 기반.

### 4.3 할일 검색 및 고급 필터링 *(Phase 2)*

**설명:** 할일 수가 늘어날수록 탐색 시간이 길어진다. 전체 할일을 대상으로 키워드 검색과 복합 필터링을 제공하여 원하는 할일에 즉시 접근할 수 있게 한다.

**기능 요구사항:**

#### FR-9: 키워드 실시간 검색

사용자는 검색창에 키워드를 입력하여 전체 할일 제목에서 실시간 검색 결과를 볼 수 있다.

**결과 (테스트 가능):**
- 입력 후 300ms 이내 결과가 갱신된다 (debounce 적용).
- 검색어가 없을 때 빈 결과가 아닌 전체 목록을 표시한다.

#### FR-10: 고급 필터링

사용자는 우선순위 / 마감일 범위 / 완료 여부 / 카테고리 필터를 개별 또는 조합하여 적용할 수 있다.

**결과 (테스트 가능):**
- 필터는 키워드 검색과 함께 AND 조건으로 적용된다.
- 적용된 필터는 시각적으로 표시되며 개별 해제 가능하다.
- "이번 주 마감 + 높은 우선순위 + 미완료" 조합이 정상 동작한다.

---

### 4.4 반복 할일 *(Phase 3)*

**설명:** 매일·매주·매월 반복되는 루틴 할일을 한 번 설정으로 자동화한다. 완료 체크 시 다음 주기 인스턴스가 자동 생성된다. 삶의 유동성을 위해 건너뛰기·일시 중지 제어를 제공한다. UJ-4를 실현한다.

**기능 요구사항:**

#### FR-11: 반복 주기 설정

할일 생성·수정 시 반복 주기(매일 / 매주 특정 요일 / 매월 특정 날짜)를 설정할 수 있다.

**결과 (테스트 가능):**
- 반복 할일 완료 시 지정 주기의 다음 마감일로 새 인스턴스가 자동 생성된다.
- 반복 설정이 없는 기존 할일 동작에 영향을 주지 않는다.

#### FR-12: 반복 유연 제어

사용자는 반복 할일에 "이번만 건너뛰기 / 일시 중지 / 반복 종료" 옵션을 적용할 수 있다.

**결과 (테스트 가능):**
- "이번만 건너뛰기" 선택 시 현재 인스턴스가 완료 없이 다음 주기 인스턴스가 생성된다.
- "일시 중지" 시 재개 전까지 새 인스턴스가 생성되지 않는다.
- "반복 종료" 시 현재 인스턴스 이후 더 이상 생성되지 않는다.

---

### 4.5 할일 묶음 템플릿 *(Phase 3)*

**설명:** 자주 반복되는 할일 조합을 템플릿으로 저장하고, 원클릭으로 여러 할일을 한 번에 생성한다.

**기능 요구사항:**

#### FR-13: 템플릿 생성 및 불러오기

사용자는 여러 할일을 묶어 이름을 붙인 템플릿을 저장하고, 언제든 불러와 한 번에 여러 할일을 생성할 수 있다.

**결과 (테스트 가능):**
- 템플릿 불러오기 시 포함된 모든 할일이 즉시 생성된다.
- 생성된 할일의 마감일은 "오늘 기준 + 원래 오프셋" 또는 사용자가 지정한 날짜로 설정된다. `[ASSUMPTION: 마감일 오프셋 방식 vs. 직접 지정 방식은 구현 시 결정]`

**범위 외 (Phase 3):** 템플릿 공유/커뮤니티 기능 (Phase 4 이후 검토).

---

### 4.6 캘린더 뷰 *(Phase 4)*

**설명:** 마감일 기준으로 할일을 월간/주간 달력에 표시한다. 마감이 몰린 날과 여유로운 날을 시각적으로 파악하고, 드래그로 마감일을 재조정한다.

**기능 요구사항:**

#### FR-14: 캘린더 뷰 표시

사용자는 캘린더 탭에서 마감일 기준 월간/주간 뷰로 할일을 볼 수 있다. 날짜 클릭 시 해당 날의 할일 목록을 표시한다.

#### FR-15: 드래그로 마감일 변경

캘린더 뷰에서 할일을 다른 날짜로 드래그하면 마감일이 자동으로 변경된다.

**결과 (테스트 가능):**
- 드래그 완료 즉시 대시보드와 카테고리 뷰에도 변경사항이 반영된다.

---

### 4.7 생산성 통계 *(Phase 4)*

**설명:** 주간/월간 완료율, 카테고리별 완료율을 차트로 시각화하여 자신의 생산성 패턴을 발견하게 한다.

**기능 요구사항:**

#### FR-16: 완료율 통계 대시보드

사용자는 통계 페이지에서 주간/월간 완료 개수와 완료율을 차트로 볼 수 있다.

#### FR-17: 카테고리별 완료율 분석

사용자는 카테고리별 완료율을 비교하여 어느 영역에서 실행력이 떨어지는지 확인할 수 있다.

## 5. 명시적 비목표 (Non-Goals)

- **팀/협업 기능:** 이 앱은 단일 사용자 전용이다. 공유, 팀 워크스페이스, 멘션 기능은 구현하지 않는다.
- **모바일 앱(네이티브):** PWA 수준의 반응형 웹만 지원한다. iOS/Android 네이티브 앱은 범위 밖이다.
- **AI 자동 할일 생성:** 자연어 처리나 AI 기반 할일 추천은 포함하지 않는다.
- **외부 캘린더 동기화:** Google Calendar, Apple Calendar 등 외부 캘린더와의 양방향 동기는 이번 로드맵에 포함되지 않는다.
- **템플릿 마켓플레이스/공유:** Phase 3 템플릿 기능은 개인 사용 한정이다. 커뮤니티 공유는 Phase 4+ 이후 별도 검토.
- **데이터 내보내기/가져오기:** CSV, PDF 내보내기는 이번 로드맵에 포함되지 않는다.

## 7. 성공 지표

**Primary**
- **SM-1:** Phase 1 완료 후 앱을 열었을 때 오늘 할 일이 **3초 이내** 파악된다. (수동 체감 기준) — FR-1~4를 검증.
- **SM-2:** Phase 2 완료 후 마감 전날 알림을 받고 앱을 여는 행동이 발생한다. (이메일 클릭 → 앱 진입 확인) — FR-6~7을 검증.
- **SM-3:** Phase 3 완료 후 매일 반복 입력이 필요 없어진다. (반복 할일 사용률) — FR-11~12를 검증.
- **SM-4 (전체):** 앱을 개인 생산성 도구로 **매일** 사용한다.

**Counter-metrics (최적화 금지)**
- **SM-C1:** 대시보드에 표시되는 항목 수를 늘리기 위해 마감일이 없는 할일을 억지로 포함시키지 않는다. 마감일 없는 할일은 카테고리 뷰에서 관리한다.
- **SM-C2:** 알림 빈도를 늘려 앱 진입을 강제하지 않는다. 알림 피로도를 방지하기 위해 최소한의 알림이 원칙이다.

## 8. 미결 사항

1. **대시보드 기본 진입점:** 로그인 후 무조건 `/dashboard`로 리다이렉트할지, 아니면 사용자가 선택 가능하게 할지.
2. **이메일 서비스 선택:** Resend, SendGrid, Supabase Edge Functions + 외부 SMTP 중 어느 것을 사용할지 (Phase 2 시작 전 결정 필요).
3. **알림 스케줄링 인프라:** Railway Cron Job vs. Supabase Edge Functions scheduled trigger — Phase 2에서 결정.
4. **반복 할일 UI 패턴:** 반복 인스턴스를 별도 항목으로 생성하는 방식 vs. 단일 항목에서 날짜를 업데이트하는 방식 — Phase 3 설계 시 결정.
5. **템플릿 마감일 오프셋:** 불러오기 시 마감일을 "오늘 + N일" 자동 설정할지, 사용자가 직접 지정할지.

## 9. 가정 사항 인덱스

- `§4.5` — 템플릿 불러오기 시 마감일 처리 방식(오프셋 vs. 직접 지정)은 구현 시 결정 예정.
