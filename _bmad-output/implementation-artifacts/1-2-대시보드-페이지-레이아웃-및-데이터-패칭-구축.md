# Story 1.2: 대시보드 페이지 레이아웃 및 데이터 패칭 구축

Status: review

## Story

사용자(Catty)로서,
로그인 후 자동으로 이동하는 `/dashboard` 페이지에서 마감일 기준 할일 데이터를 불러오는 것을 원한다,
카테고리를 탐색하지 않고도 할일이 시간 섹션으로 구조화되어 보이는 전용 공간을 갖도록.

## Acceptance Criteria

1. **queryKeys 중앙화**: `lib/queryKeys.ts`가 생성되고, TanStack Query를 사용하는 모든 파일에서 `queryKeys.todos.dashboard()`, `queryKeys.todos.all` 등 중앙화된 키로만 쿼리에 접근한다. 컴포넌트·훅 파일 내에서 쿼리 키 문자열 리터럴 직접 사용 금지.

2. **루트 리다이렉트**: 로그인한 상태에서 앱 루트(`/`)에 접근하면 `/dashboard`로 자동 리다이렉트된다.

3. **로딩 스켈레톤**: `/dashboard` 페이지에서 데이터 로딩 중일 때 `app/dashboard/loading.tsx`의 스켈레톤 UI가 표시되고 레이아웃이 깨지지 않는다.

4. **4개 섹션 렌더링**: 데이터 로딩 완료 후 "기한 초과", "오늘 마감", "내일 마감", "이번 주 마감" 섹션 영역이 각각 존재한다. `hooks/useDashboard.ts`가 `lib/api.ts`를 통해 `GET /todos/dashboard`를 호출한다.

5. **에러 처리**: API 호출이 실패할 때 앱이 크래시되지 않고 빈 섹션들이 표시된다. 한국어 에러 메시지가 토스트 또는 에러 영역에 표시된다.

### 핵심 제약 사항 (절대 위반 금지)

- **`queryKeys.ts` 외부에서 쿼리 키 문자열 리터럴 사용 금지**: `useQuery`의 `queryKey`는 반드시 `queryKeys` 객체를 통해서만 접근
- **날짜 경계 계산 프론트엔드 금지**: API 응답(`overdue`, `today`, `tomorrow`, `this_week`)을 그대로 렌더링. 클라이언트에서 날짜 재분류 금지
- **API 호출 `lib/api.ts` 단일 진입점**: 컴포넌트/훅에서 직접 `fetch` 호출 금지 → `lib/api.ts` 함수만 사용

### `lib/api.ts` — getDashboardTodos 구현 패턴

```typescript
// frontend/src/lib/api.ts
import { createClient } from '@/lib/supabase/client';
import type { DashboardResponse } from '@/types/dashboard';

export async function getDashboardTodos(): Promise<DashboardResponse> {
  const supabase = createClient();
  const { data: { session } } = await supabase.auth.getSession();
  
  if (!session?.access_token) {
    throw new Error('인증이 필요합니다.');
  }

  const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/todos/dashboard`, {
    headers: {
      Authorization: `Bearer ${session.access_token}`,
      'Content-Type': 'application/json',
    },
  });

  if (!res.ok) {
    throw new Error(`API 오류: ${res.status}`);
  }

  return res.json() as Promise<DashboardResponse>;
}
```

// frontend/src/lib/supabase/server.ts (서버 컴포넌트/미들웨어용)
import { createServerClient } from '@supabase/ssr';
import { cookies } from 'next/headers';

export async function createClient() {
  const cookieStore = await cookies();
  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll: () => cookieStore.getAll(),
        setAll: (cookiesToSet) => {
          cookiesToSet.forEach(({ name, value, options }) =>
            cookieStore.set(name, value, options)
          );
        },
      },
    }
  );
}

### 미들웨어 리다이렉트 패턴

```typescript
// frontend/src/middleware.ts
import { createServerClient } from '@supabase/ssr';
import { NextResponse, type NextRequest } from 'next/server';

export async function middleware(request: NextRequest) {
  let supabaseResponse = NextResponse.next({ request });
  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll: () => request.cookies.getAll(),
        setAll: (cookiesToSet) => {
          cookiesToSet.forEach(({ name, value, options }) =>
            supabaseResponse.cookies.set(name, value, options)
          );
        },
      },
    }
  );

  const { data: { user } } = await supabase.auth.getUser();
  const url = request.nextUrl;

  if (url.pathname === '/' && user) {
    return NextResponse.redirect(new URL('/dashboard', request.url));
  }
  if (url.pathname === '/' && !user) {
    return NextResponse.redirect(new URL('/login', request.url));
  }

  return supabaseResponse;
}

export const config = {
  matcher: ['/', '/dashboard'],
};
```

### Story 1.1 인증 패턴 (backend/dependencies.py)

백엔드가 `HTTPBearer` 방식 사용. 프론트에서 반드시 `Authorization: Bearer {access_token}` 헤더 포함 필요. Supabase `session.access_token`이 JWT 토큰임. `getSession()` 대신 `getUser()`를 사용하면 서버 검증됨 (보안 강화, 권장).

### 기존 코드베이스 확인 사항

- `frontend/` 디렉토리가 **없으므로** Task 1 필수 실행
- `backend/main.py`의 CORS 설정이 `allow_origins=["*"]`이므로 개발 중 CORS 문제 없음. 배포 시 도메인 제한 필요
- 백엔드 `id` 필드는 `str` (UUID) — TypeScript 타입도 `string`
